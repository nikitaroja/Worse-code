# Руководство разработчика

Как Worse Code устроен внутри и как его расширять. [English version](DEVELOPER_GUIDE.md)

## 1. Структура репозитория

```
wc.py                  интерпретатор (конфиг, разбор блоков, цикл выполнения)
wcsg.py                модуль WCSG: окна, чёрная консоль, холст (нужен tkinter)
wc_modifier.py         WC Service Modifier: окно настроек (tkinter, русский интерфейс)
wc_exe_maker.py        собирает .exe для папки с программой (PyInstaller)
wc_config.example.json все ключи конфига со словами по умолчанию
examples/              небольшие программы, в каждой папке есть start.wc
projects/              твои программы
docs/                  это руководство
```

`wcsg.py` подключается только командой `load`, поэтому программам без окон tkinter не нужен.

## 2. Устройство на одной странице

- **По строкам.** Программа это список `(номер_строки, текст)` без комментариев и пустых строк. Первое слово строки это команда, остальное её аргумент.
- **Выражения это Python.** Аргумент большинства команд проходит через `eval(выражение, variables)`. Словарь `variables` служит *глобалами* для `eval`, поэтому даже генераторы списков видят все переменные. В нём лежат переменные программы, а также `year`, `random` и (после `load`) `waitkey`.
- **Блоки сопоставляются до запуска.** `build_blocks` один раз проходит по программе и запоминает, где какой `if`, цикл, `else` и `end`. Цикл выполнения прыгает по счётчику команд, так что цикл это просто «прыжок назад».
- **Слова берутся из конфига.** Код не сравнивает с `"say"`, он сравнивает с `cfg["say"]`. Зафиксированы только `sleep`, `exit`, `quit`, `clear`, `rect`, `circle`.
- **GUI это плагин.** `wc.py` общается с `wcsg.py` через несколько функций (раздел 4).

## 3. wc.py

| Часть | Что делает |
|---|---|
| `DEFAULTS` | все настраиваемые слова и значения по умолчанию |
| `load_config(program_dir)` | слои: `DEFAULTS`, потом `wc_config.json` рядом с `wc.py`, потом `wc_config.json` рядом с программой |
| `strip_comment` | убирает комментарий, но не трогает символ комментария внутри кавычек |
| `read_value` | преобразование для `ask`: `int`, потом `float`, иначе текст |
| `build_blocks` | возвращает `kinds`, `end_at`, `else_at`, `opener_of` (словари индексов) и бросает `BlockError` с номером строки |
| `run_program` | цикл выполнения |
| `main` | аргументы (`--pause`), чтение файла, вызов `run_program` |

**Таблицы блоков.** Индексы указывают в список `program`. `kinds[i]` это `"if"`, `"while"` или `"for"` для открывающей строки `i`. `end_at[i]` это индекс её `end`, `else_at[i]` индекс её `else`, а `opener_of[j]` ведёт от `else` или `end` обратно к открывающей строке.

**Цикл выполнения.** `pc` это счётчик команд. На каждом шаге `here = pc; pc += 1`, потом команда выполняется и может перезаписать `pc`:

- `if`: если условие ложно, прыжок на строку после `else` или после `end`.
- `else`: сюда попадают только из истинной ветки, поэтому прыжок за `end`.
- `end`: для `while` и `for` прыжок назад на открывающую строку, которая заново проверяет условие.
- у циклов есть стек `loops` из словарей (`start`, а у `for` ещё `items` и `pos`). Открывающая строка при повторном заходе видит `loops[-1]["start"] == here` и продолжает тот же цикл.
- `break` снимает верхний цикл со стека и прыгает за его `end`.

**Порядок веток** в цепочке `try` важен: сначала слова блоков, потом `load` и слова зоны GUI, потом `say / set / do / ask / sleep / exit`, потом слова холста, потом строки окон (только внутри зоны) и в самом конце «не понимаю».

**Маршрутизация консоли.** `use_gui_console()` истинно внутри зоны или после `force_noecho`. По нему `out()` и `ask` выбирают между `print` / `input` и `gui.console_print` / `gui.console_ask`. Перед печатью ошибки `fail()` возвращает настоящую консоль, иначе скрытая консоль проглотила бы сообщение.

**Приём с `set`.** Простое имя сохраняется напрямую. Всё остальное (`a[0]`, `a, b`) идёт через `exec(f"{target} = __value", variables)`, где значение временно лежит под именем `__value`.

**Ошибки.** Всё в цикле обёрнуто в `try/except Exception` и выводится как `Error on line N: ...`. `SystemExit` (его бросают `exit` и закрытие холста) проходит к `finally`, где вызывается `gui.shutdown()`.

## 4. wcsg.py

**Жизненный цикл.** `get_root()` создаёт один скрытый `tk.Tk()`. Каждое окно это `Toplevel` от него. Обычный `mainloop` не запускается: окна блокируют программу через `wait_window` или `root.wait_variable(...)`, а анимация идёт через `update()` и `root.after`. `shutdown()` возвращает консоль, забывает консоль и холст и уничтожает корень.

**Грамматика строки окна.**

```
строка   := пресет { "]" параметр [ значение ] }
параметр := один из VALUE_PARAMS или FLAG_PARAMS
```

`split_outside_quotes(line, "]")` режет по `]`, но не внутри строк. `parse_line` возвращает `(preset, opts)`: проверяет имена, вычисляет значения через `eval(rest, variables)`, разбирает флаги в `parse_flag` и заполняет `opts` (значения по умолчанию берутся из пресета: `size`, `resizable`, `anykey`).

**Показ окна.** `show_window` строит `Toplevel`, рисует иконку (`draw_icon` на `Canvas` или `load_icon` для `windowicon`), добавляет кнопки по `kind` пресета (`ok`, `yesno`, `okcancel`, `input`, `blank`) или свои `button`, подключает клавиши и перетаскивание, ставит окно через `place`, ждёт и кладёт результат в `opts["save"]`.

**Консоль.** `console_open` один раз создаёт чёрное окно с `Text`. `console_print` добавляет строку и вызывает `update()`. `console_ask` добавляет поле и кнопку Done и ждёт `IntVar`. `console_finish` ждёт любую клавишу или клик. Функция `release` в словаре состояния позволяет кнопке закрытия прервать ожидание.

**Холст.** `canvas_open`, `canvas_clear`, `canvas_rect`, `canvas_circle`, `canvas_text`, `canvas_finish`. Состояние лежит в `_canvas` (`win`, `surface`, `keys`, `closed`, `wake`). `waitkey(ms)` очищает `keys`, ждёт через `_wait` (он не даёт окну замёрзнуть) и возвращает последнюю клавишу. Закрытый холст заставляет `_need_canvas` бросить `SystemExit`.

**Скрытие консоли.** `set_terminal_visible` вызывает `GetConsoleWindow` и `ShowWindow` через `ctypes` внутри `try/except`, поэтому в других системах она просто ничего не делает.

## 5. Конфиг и Modifier

`wc_modifier.py` импортирует `DEFAULTS` из `wc.py` и `PRESETS` / `POSITIONS` из `wcsg.py`.

- `COMMANDS`: `(ключ конфига, описание, пример)` для каждой строки таблицы настроек. В `example` подставляется текущее слово вместо `{kw}`. `None` скрывает строку из справки.
- `WORD_KEYS`: ключи, которые должны быть одним словом, уникальными и не начинаться с символа комментария. Проверку делает `save()`.
- `refresh_help()` строит вкладку справки по текущему конфигу. Обновляй её при добавлении команд.

## 6. Создатель .exe

`wc_exe_maker.py <папка>` проверяет наличие `start.wc`, копирует папку в `<имя>_release`, добавляет `wc.py`, `wcsg.py`, `wc_config.json`, если их нет, и собирает через PyInstaller крошечный запускатор (`--onefile`, `--noconsole` по запросу, `icon.ico` если он есть). Исходник запускатора это строка `LAUNCHER`. Во время работы он ищет Python (`py -3`, `python`, потом `python_windows.exe`), пропускает заглушку Microsoft Store (`WindowsApps`), запускает `wc.py start.wc` в своей папке и показывает окно с сообщением, если Python нет. Ключи: `--console`, `--noconsole`, `--no-build` (только копирование, удобно для тестов).

## 7. Рецепты

**Новая команда, которую можно переименовать**

1. `wc.py`: добавь `"pause": "pause"` в `DEFAULTS`.
2. `wc.py`: добавь ветку перед веткой `canvas_words`:

```python
elif word == cfg["pause"]:
    input("Press Enter to continue...")
```

3. `wc_modifier.py`: добавь `("pause", "Ждать Enter", "{kw}")` в `COMMANDS` и `"pause"` в `WORD_KEYS`.
4. Добавь строку в таблицу команд в README.

**Новая функция для выражений.** Добавь её в словарь `variables` в начале `run_program`:

```python
variables = {
    "year": datetime.now().year,
    "random": random.randint,
    "clamp": lambda value, low, high: max(low, min(high, value)),
}
```

**Новый пресет окна.** Добавь запись в `PRESETS` в `wcsg.py`. `kind` это `ok`, `yesno`, `okcancel`, `input` или `blank`, а `icon` это имя, известное `draw_icon`, или `None`:

```python
"notice_window": {"icon": "info", "title": "Notice", "text": "", "kind": "ok",
                  "about": "info icon, OK button"},
```

**Новый параметр окна** (например `padding 30`): добавь `"padding"` в `VALUE_PARAMS`, задай значение по умолчанию в `opts` внутри `parse_line`, разбери его (`elif param == "padding": opts["padding"] = int(value)`), потом используй в `show_window` (`body.pack(padx=opts["padding"], ...)`). Опиши его в таблице README.

**Новая команда холста** (например `line`): напиши `canvas_line` в `wcsg.py` и добавь `"line": "canvas_line"` в `canvas_words` в `wc.py`:

```python
def canvas_line(x1, y1, x2, y2, color="white", width=2):
    _need_canvas()["surface"].create_line(x1, y1, x2, y2, fill=color, width=width)
```

## 8. Тестирование

Набора тестов пока нет. Перед каждым изменением:

1. Запусти все программы из `examples/` (`python wc.py examples/<имя>/start.wc`).
2. Проверь ошибки: нет `end`, `end` без блока, `forcequit` вне цикла, строка окна вне зоны.
3. Логику, которой не нужен экран, можно проверить, заменив tkinter заглушкой, а функцию окна на `print`. Это работает на любой машине:

```python
import sys, types
tk = types.ModuleType("tkinter"); tk.TclError = Exception
sys.modules["tkinter"] = tk
import wc, wcsg

wcsg.show_window = lambda preset, opts, variables, d, rv: print(preset["title"], opts["text"])
program = ['load standrt_gui', 'wcsgstart', 'Error_window ] speak ("hi")', 'wcsgstophere']
wc.run_program(program, wc.load_config(), ".")
```

4. Настоящие окна можно проверить только запуском на Windows: посмотри каждый пресет, консоль, `force_noecho`, холст и закрытие окон крестиком.

## 9. Соглашения

- Сообщения для пользователя на английском. Комментарии пиши редко и коротко, лучше давай понятные имена.
- Никаких новых обязательных зависимостей. Необязательные (Pillow) должны корректно отключаться.
- Модули должны импортироваться без побочных эффектов: `main()` закрыт условием `if __name__ == "__main__"`.
- Всё, что работает только на Windows, оборачивай в `try/except`, чтобы другие системы не ломались.
- Новое слово языка требует: `DEFAULTS`, ветку выполнения, списки в Modifier, строку в таблице README.

## 10. Чек-лист релиза

1. Запусти примеры и проверь ошибки.
2. Обнови версию в обоих README.
3. Собери `.exe` для тестового проекта и запусти его на ПК без Python (с `python_windows.exe` и без).
4. Создай релиз на GitHub (тег `v1.0`, `v1.1`...) и прикрепи туда ZIP и `.exe`.

## 11. Идеи

Собственные функции, `elif`, мышь на холсте, звуки, режим «всё внутри .exe», где PyInstaller упаковывает интерпретатор и Python не нужен, перевод интерфейса Modifier на английский.

## О написании названия

Имя модуля `standrt_gui` это историческое написание, и оно остаётся для совместимости. `standart_gui` принимается как синоним.
